## What this is

A graded full-stack assignment (Berkeley, Assignment 1: Secure Networking Tracker) built
as a real product: a private per-user contact tracker where ownership is enforced by
Postgres row-level security rather than by application code. On top of the assignment
sits an optional, local-only sync that populates it from the Obsidian vault.

The core constraint that shaped everything: **no component in the request path holds a
credential that bypasses RLS.** The Express API has no connection string and no Postgres
driver; it forwards the end user's own JWT to the Neon Data API, so RLS applies to every
query it makes.

## Architecture

```
apps/web        React 19 + Vite + TS + Tailwind v4      → Vercel project A (static)
apps/api        Express 5 + TS (ESM)                    → Vercel project B
apps/sync       local-only wiki sync CLI                → NEVER deployed
packages/shared one Zod validation contract + merge rule (pure, tested first)
db/migrations   001 contacts + RLS · 002 wiki-sync columns
db/migrate.mjs  applies migrations via `pg` (no psql dependency)
scripts/check-no-secrets.sh
.claude/skills/strada-sync
```

Request path: browser → Express (CORS → JWT verify via JWKS → Zod) → Neon Data API
(PostgREST) → RLS → Postgres. Express builds every upstream URL itself and forwards only
`Authorization` and `Content-Type`.

Build: `npm run build` (workspaces). `packages/shared` has a `prepare` script so its
`dist/` exists after any install.

## Key decisions (do not relitigate)

- **The database enforces ownership, not the API.** The API is fail-fast and UX only. The
  Data API is reachable by any signed-in user with their own token, so RLS and CHECK
  constraints are the enforceable guarantees. The README says this explicitly rather than
  overclaiming.
- **`id` is uuid, not a sequential integer.** Constraint checks run outside RLS, so a
  client-suppliable integer key leaks cross-user row existence through duplicate-key
  errors.
- **`FORCE ROW LEVEL SECURITY`.** Without it the table owner bypasses every policy, which
  is the role a migration or `psql $DATABASE_URL` connects as.
- **No route accepts a client filter.** Ids come from path parameters; an unfiltered
  `DELETE` would wipe all of the caller's own rows.
- **RLS proof runs over HTTP with two real accounts,** not through `pg` — a direct
  connection is the table owner and would pass with the policies deleted. It fails loudly
  when unconfigured rather than skipping.
- **Wiki sync is local-only and read-only.** The vault is on the laptop, Strada is on
  Vercel; a sync button in the deployed app is impossible by construction. Nothing writes
  back to the vault. Verified by checksumming entity pages before and after runs.
- **Only derived fields leave the machine.** Extraction runs on a local model
  (`gemma-4-31b-it-mlx` via LM Studio); page text never leaves. The vault holds other
  people's names and candid assessments, so a hosted model is not an option.
- **Operator edits are sticky per field.** Editing in the app claims that field; sync
  reports the refusal instead of overwriting. `POST /api/contacts/:id/reclaim` hands it
  back — without that, contacts ossify.
- **The secret check must fail only when something is wrong.** It has been corrected
  twice in opposite directions: v1 grepped the bundle for variable *names*, which Vite
  never emits, so it could not fail; v2 treated `NEON_AUTH_BASE_URL` as secret and failed
  on every correct build, because that URL is the sign-in endpoint the browser must call
  and ships on purpose as `NEXT_PUBLIC_NEON_AUTH_URL`. Current version drops it and checks
  the real risk instead — a secret's value copied into a `NEXT_PUBLIC_`/`VITE_` name —
  outside the `dist/` guard, verified in both directions.
- **Sync password lives in the macOS keychain**, not `.env.local`. Resolution order:
  keychain → interactive prompt → env var (warns).
- **Model copied to `~/.lmstudio/models`** so sync does not depend on the CACHE drive
  being mounted. `~/.lmstudio/settings.json.bak-strada` restores the old setting.

## Run / test / deploy

```bash
# setup
npm install
cp .env.example .env.local        # then fill in
npm run migrate                   # then refresh the Data API schema cache in Neon

# dev
npm run dev:api                   # :3001
npm run dev:web                   # :5177  (strictPort; 5173 is taken by another project)

# test
npm test                          # 104 hermetic, no credentials needed
npm run test:rls                  # 12 live, needs two accounts; fails loudly if unset
npm run check:secrets

# wiki sync (local only)
~/.lmstudio/bin/lms ps            # a model must be loaded, or the CLI stops
npm run sync:login                # once; stores the password in the keychain
npm run sync -- --dry-run
npm run sync

# deploy
git push origin main              # both Vercel projects build from main
```
